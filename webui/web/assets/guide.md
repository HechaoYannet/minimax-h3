# MiniMax-H3 创作台 · 使用说明

这是一个套在当前工程外面的**操作前端**：左边写中文创作意图，中间调参数，右边看进度和硬件占用。
提示词优化接 DeepSeek，生成仍然走工程原本的 `run_h3.sh gen`，一条流水线都没改。

## 一、一分钟上手

1. **写中文意图**。不用管英文规范，也不用背镜头术语，把「谁 / 在哪 / 干什么 / 镜头怎么动 / 有什么声音」说清楚就行。
2. **（可选）加参考素材**。点输入框上方的  或「参考素材」卡片里的按钮：
   - 一张图 → 会被当作**首帧**（官方 I2VA）；
   - 两张图 → 首帧 + 尾帧（FL2VA）；
   - 图 / 视频 / 音频混用 → 全参考 Ref2VA；
   - 想做「改视频」→ 加**视频+音轨**（官方 tav2va 用法，也是「编辑」页签对应的模式）。
3. **点「✦ 优化提示词」**。DeepSeek 会按 `references/` 里的官方规范，把中文改写成结构化英文提示词；
   三个页签分别是**英文提示词**（真正送进流水线的）、**中文回译**（给你校对，防止模型理解跑偏）、**结构说明**。
4. **看预估**。参数卡片右上角一直显示：`seq` 长度、`s/步`、去噪耗时、总计、风险提示。
   觉得贵就先切 `blitz` 或 `fast` 预设试构图。
5. **点「开始生成」**（或 `Ctrl+Enter`）。右边监控面板会实时显示阶段、步数、ETA、显存、日志。

## 二、预设怎么选

预设来自 `cache/plan.json`，是工程里量过的档位，不是拍脑袋写的：

| 预设 | 形状 | 步数 | 工程里的说法 |
|---|---|---|---|
| `blitz` | 640×384×22 | 8 | 约 46 s 出片，试种子 / 试构图 |
| `fast` | 640×384×39 | 10 | 性价比拐点，约 87 s |
| `draft` | 640×384×73 | 20 | 实测 4.7 min 出片（本机默认起点） |
| `preview` | 832×480×73 | 30 | 预览 |
| `standard` | 832×480×124 | 30 | 交付档，实测约 17 min |
| `quality` | 1024×576×124 | 30 | 本机跑通的最高画布，约 25 min |
| `max-long` | 640×384×243 | 20 | 最长可用（10.12 s 视频） |
| `video-edit` | 832×480×124 + 参考视频 | 30 | 官方 tav2va |
| `max-native` | 1344×768×124 | 50 | 官方原生档：**本机跑不了，会 OOM** |

**两条铁律**：

- **时长和分辨率只能二选一。** 8 GiB 显存下，1024×576 只能到 124 帧；想更长就得把画布压到 640×384。
- **长片段一律把 `DiT 装载方式` 改成 `disk`。** `cpu` 会把 9.76 GiB 的 DiT 常驻内存，
  再叠加文本编码器的 14.27 GiB mmap 会顶到 WSL 的 22.9 GiB 配额 —— 工程里曾经因此把整个 WSL 打死过一次。

## 三、参数说明（每个都有为什么）

### 形状与时长

- **宽度 / 高度**：必须是 32 的倍数，否则框架会自己向上吸附，你拿到的片段和你以为的不一样。
- **帧数**：合法网格是 `帧数 % 17 == 5`（22、39、56、73…）。
  **但下限按实测要取 22** —— 5 帧、6 帧这类值能通过框架的形状检查，
  却会在 VAE 解码阶段直接报 `'NoneType' object has no attribute 'float'`（实测复现过）。
  243 帧是 640×384 档实测跑通的最长片段，再长请先降画布。
- **时长**：24 fps，帧数 ÷ 24。73 帧 = 3.04 s。
- **采样步数**：`blitz` 那种 8 步适合试构图；定稿 20~30 步。挂 LoRA 时低于 20 步容易出音频瑕疵。

### 参考条件的代价（最容易被忽视的杠杆）

- **参考图短边**：框架默认 2048，对一张 1024² 参考图会多花 **54% 的注意力**；改成 1024 只要 12%。
  这是本工程改过的默认值（`draft` 甚至用 256）。做人物一致性时可以单独 A/B 1024 vs 1536。
- **参考视频短边**：参考视频与目标等长，代价比图大得多 —— 768 会让序列翻到 2.05 倍，384 是 1.49 倍。

### 显存 / 内存 / 速度

- **显存阈值 `vram_limit`**：它是「整卡已用量」的阈值，不是权重预算。抬高只多常驻几层，
  实测 4.58 → 6.30 时单步 13.17 → 13.34 s，**基本没用**，但余量只剩不到 1 GiB。默认 4.58 就好。
- **激活预留 `activation_reserve`**：比 `vram_limit` 直观，按
  `vram_limit = 启动可用 − 激活预留 − LoRA` 反推。
- **DiT 装载方式**：`cpu` 常驻内存（峰值 11.1 GiB）/ `disk` 走 mmap（峰值 4.8 GiB，长片段更快更稳）。
- **注意力后端**：DiT 走 SDPA，实测 cuDNN 最快，保持 `cudnn`。

### LoRA 与调度器

- 挂上 LoRA 后，调度器会自动切到 **beta** —— 这是 AfterMidnight 的硬性要求（euler + beta，否则音频会出问题）。
  想强制可以用 `scheduler` 字段覆盖，但会被警告。
- `LoRA 权重`（alpha）控制强度，1.0 是作者标定值。

## 四、防呆：页面会拦住你

- **形状吸附提示**：帧数/分辨率不合法时，预估面板会明确写出「会被吸附成什么」。
- **越界即时报错**：帧数、步数、提示词长度、素材扩展名都在提交前校验（后端再校验一遍）。
- **致命配置二次确认**：判定为「大概率失败」的配置（比如 seq ≥ 30000）会弹窗，要点「仍然要跑」才提交。
- **一次 OOM 污染全局**：工程里实测过一次 OOM 之后，后续所有配置都会失败；
  页面在 OOM 后给出的建议里包含 `wsl --shutdown` 这一步。
- **单作业串行**：同时只跑一条流水线，后面的自动排队 —— 8 GiB 卡上并发必然 OOM。

## 五、常见错误对照表

| 页面/日志里看到 | 真实原因 | 怎么办 |
|---|---|---|
| `CUDA out of memory` | 显存不够 | 降分辨率/帧数；OOM 后先 `wsl --shutdown` |
| `Failed to create GPU mapping` | 驱动级报错，通常还是 OOM | 关掉 Windows「共享 GPU 显存」，见工程 README §10.3 |
| `device not ready` | 上一次 OOM 的后遗症 | `wsl --shutdown` 重启 WSL 再跑 |
| `Killed` | 主机内存不足 | 改用 `dit_onload=disk`，降低帧数 |
| `没有配置 DeepSeek API Key` | 没填 key | 见下一节 |
| `HTTP 401` / `402` | Key 无效 / 余额不足 | 检查 `config/deepseek.yaml` |
| 参考素材 `不存在` | 路径在 WSL 里不存在 | 用「+ 路径」把 Windows 路径粘进去，后端会自动翻译成 `/mnt/d/...` |

## 六、提示词优化接的是哪个模型

配置在 `config/deepseek.yaml`（**只有这一个文件**）：

- `api.url` / `api.key`（也可以留空改用环境变量 `DEEPSEEK_API_KEY`）
- `model.name`：`deepseek-chat` 或 `deepseek-reasoner`
- `model.thinking`：思考模式开关与强度（`reasoning_effort`）
- `prompt.system_prompt_file`：system prompt 文件，默认 `config/prompts/system.md`
- `prompt.mode_digests`：三种结构规范（Ref2VA 六段式 / 单图关键帧 / 纯文本）

**为什么中英要分开**：参考文档（`references/base-en.md`、`ref-en.md`）是英文提示词规范，
而使用者是中文用户。所以优化流程是「中文进 → 结构化英文出 → 附带中文回译」，
英文那一段直接送进流水线，中文那一段给你核对。回译里结构字段名和 `<Picture n>` 这类标签保持英文原样，
其余说明是中文 —— 这样既能读懂，又不会让人误以为标签可以翻译。

## 七、前端和生成系统是怎么解耦的

- 前端只跟 WSL 里的一个小 HTTP 服务说话（REST + SSE），**不 import 任何生成代码**。
- 生成是**子进程**：后端拼出 `run_h3.sh gen …` 参数并拉起它，作业失败不会拖垮服务。
- 唯一的侵入点：`scripts/h3_generate.py` 里有个 20 行左右的进度钩子，
  由环境变量 `H3_PROGRESS_JSONL` 触发，不设它就完全不生效（终端用法一模一样）。
- 于是：**把 webui/ 整个目录删掉，工程照旧能用**；反之改了生成脚本，最坏情况也只是进度曲线没了。

细节与协议见 `webui/README.md`。
